# ADR 0009：编辑器 UI 后端选型

- 日期：2026-11-18
- 状态：Proposed（待 M12 spike 后定稿）
- 关联：README §5.7、§9.15、§11.6

## 背景

编辑器需要 UI 框架承载面板、Inspector、内容浏览器与视口合成。候选为 GPUI、egui 或自研最简宿主。
关键顾虑：事件循环归属、与 Vulkan 视口的纹理共享、API 稳定性、许可证与传递依赖。
结论需在 M12 前通过 spike 形成，本 ADR 先记录决策框架与当前倾向。

## 决策

1. **编辑器核心与 UI 框架解耦**：`mir-editor-core` 是与 UI 框架无关的状态机——文档/关卡、选择、命令栈、
   Inspector 模型、视口相机/Gizmo 数学、拾取、PIE 会话、资产浏览器模型；
   **不依赖** UI 框架、窗口库或 Vulkan。
2. **UI 契约**：`mir-editor-ui` 定义 UI 宿主接口、事件映射与视口目标；
   `mir-editor-gpui`（候选）、`mir-editor-egui`（备选）实现该契约；`miriya-editor` 是组合根，按 feature flag 选择后端。
3. **视口**：由 `mir-render`（vulkanalia）渲染到引擎自有 surface 或离屏纹理，UI 后端负责合成/呈现；
   编辑器核心不接触 GPU。
4. **事件循环**：由 UI 宿主实现（GPUI 自带；egui 由 winit 适配层驱动）；PIE 是核心驱动的子会话。
5. **默认后端选型（待定）**：M12 spike 评估 GPUI 的事件循环/纹理共享/许可证与稳定性；不可行则用 egui 或自研最简宿主。
   若 GPUI 自带 GPU 渲染器，它只负责编辑器 chrome，不改变游戏/视口的 Vulkan 后端；若无法共享纹理或事件循环，
   优先离屏合成/子表面适配；若要求 chrome 也走 vulkanalia 则实现 GPUI-on-Vulkan 适配，仍不可行则回退 egui。
6. **许可证评审**：GPUI/egui 的许可证、传递依赖与 API 稳定性必须评审（§11.6），任何 UI 框架都不得进入运行时依赖。
7. **headless**：核心测试不启动 UI；UI 后端只做冒烟测试；切换后端不得改动核心逻辑。
8. **不做**：Sequencer/Niagara、蓝图编辑器、内置 C# 代码编辑器（C# 用外部 IDE）。
9. **验收**：核心 headless 测试全绿；选定后端可编辑/保存/PIE，视口由 vulkanalia 渲染。

## 替代方案

- **GPUI**（候选）：现代、Rust 原生、自带渲染器，但纹理共享/事件循环与许可证仍在评估。
- **egui**（备选）：轻量、集成简单，但视觉与复杂编辑器交互能力有限。
- **自研最简宿主**：完全可控，但面板/布局/文本输入等基础控件工程量不小。
- **让运行时 UI（mir-ui）兼做编辑器**：违反「编辑器 UI 与运行时 UI 完全解耦」（§9.14）。

## 后果

- 正面：核心与 UI 解耦使得后端切换是组合根层面的 feature 选择，不影响编辑器逻辑与运行时。
- 负面：需维护 UI 契约与适配层；默认后端未定，M12 前存在不确定性。
- 后续：M12 spike 后把状态改为 Accepted，并补充具体的纹理共享/许可证结论。

# ADR 0003：坐标系与单位约定

- 日期：2026-11-18
- 状态：Accepted
- 关联：README §9.2、§9.9

## 背景

必须固定全局坐标约定，否则数学、渲染、物理、资产导入各自 flip 轴，导致难以定位的符号错误。
UE 生态的美术资产与教程使用厘米、Z-up、左手系；Vulkan NDC、glTF 与外部物理后端各有自己的约定。

## 决策

1. **全局约定**：厘米为单位、Z-up、左手系、X 前、Y 右，与 UE 对齐（README §9.2）。
2. **类型层固定**：`mir-math` 用 newtype（`#[repr(transparent)]` + `Deref`）封装 `glam` 类型，补齐
   `Transform`、`Aabb`、`Frustum`、`Ray`、`Plane`、`Color`；坐标语义在类型注释中写明。
3. **转换集中在 `interop` 模块**：
   - 投影矩阵在**相机边界**转到 Vulkan 约定（深度 0..1、NDC Y 向下）；
   - 物理后端 Z-up ↔ 后端约定（§9.9）、glTF Y-up 的转换只允许在 `interop` 出现。
4. **禁止业务代码手写坐标翻转**；发现即视为评审阻塞项。
5. 测试覆盖手性、投影、裁剪、四元数插值；后续用 `bytemuck::Pod` 支持 GPU 零拷贝。
6. `Transform` 归 `mir-math` 所有，M3 把现有 `mir-scene::Transform` 迁移并重导出，保持应用层导入路径稳定。

## 替代方案

- **Y-up / 右手系（glTF / Vulkan 原生）**：少一次转换但失去 UE 资产与美术习惯的对齐，迁移成本高。
- **各子系统自行转换**：短期灵活，长期必然出现多处不一致的 flip，调试成本极高。
- **运行时动态配置手性**：增加分支与测试矩阵，无实际收益。

## 后果

- 正面：单一约定 + 集中转换，使渲染/物理/导入边界清晰可测；美术与 UE 参考资料可直接复用。
- 负面：每个边界（相机、物理、glTF）都必须写转换并测试，增加 `interop` 模块维护量。
- 验收：所有跨约定转换必须有对应单元测试；投影/裁剪测试是 M2 渲染的准入门槛。

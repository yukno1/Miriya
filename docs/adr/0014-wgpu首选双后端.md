# ADR 0014：wgpu 首选、Vulkan 保留的双后端渲染

- 日期：2026-11-28
- 状态：Accepted
- 取代：ADR 0005（“Vulkan 唯一图形后端”标记为 Superseded，保留原文作为历史）
- 关联：ADR 0004、ADR 0011、ADR 0012；README §5.1、§9.6、§11、§14

## 背景

ADR 0005 选择 Vulkan 单后端以控制早期复杂度；M2 已在 `mir-render` 中落地完整的 Vulkan 1.3
绘制链路（交换链、RenderGraph、显存子分配器、材质/PBR、GPU 时间戳）。随着 wgpu 生态成熟，
需要在不推翻既有投入的前提下，让默认渲染路径获得跨平台抽象能力与更低的驱动门槛。

现有 `mir-render` 公共 API 已经是后端中立的纯数据边界（`CameraFrame` / `InstanceData` /
`MeshData` / `MaterialData` / `TextureData` 与世代句柄），Vulkan 类型全部封装在 `vulkan/` 子模块，
因此新增后端不需要改变 extract 边界。

## 决策

1. **双后端，wgpu 优先**：默认 `BackendPreference::Auto` 按 `wgpu → Vulkan` 顺序尝试；
   某后端失败时自动回退并记录原因。可使用 `--backend=wgpu|vulkan|auto` 或
   `EngineConfig::backend` 强制指定；强制模式下失败不回退。
2. **公共 API 不变**：只新增 `BackendKind`、`BackendPreference`、`RenderContext::backend_kind()`
   与 `RendererStatus::Wgpu { .. }`；`mir-render` 不向外部暴露 wgpu 或 Vulkan 类型。
3. **内部静态分发**：`backend.rs` 用 `enum ActiveBackend { Wgpu, Vulkan }` + `match` 委派所有操作，
   不引入 `dyn Trait`，与 README §5.1 的“后端选择优先 enum + match”一致。
4. **共享契约**：相机 UBO（80 B）、push constants、帧在飞行数（2）、槽位上限与世代槽位表
   （`resource_table.rs`）由两后端共用；`graph::build_frame_graph` 是纯数据声明，RenderGraph
   编译器与 DOT dump 两后端复用。
5. **着色器仍为 Slang → SPIR-V（ADR 0011 不变）**：复用现有 `pbr.spv`（单文件双入口）。
   wgpu 30 经 naga 的 SPIR-V 前端将其中的 Vulkan `PushConstant` 翻译为 `var<immediate>`：
   设备请求启用 `Features::IMMEDIATES` 与 80 B 的 `max_immediate_size`，运行时用
   `RenderPass::set_immediates` 写入（旧版 `set_push_constants` 在 wgpu 30 已移除）。
6. **RenderGraph 语义差异**：wgpu 自带资源状态跟踪，因此 wgpu 后端只消费 `pass_order`、
   图校验与 DOT dump，**不翻译 barrier**；Vulkan 侧 barrier/layout 推导保持不变。
7. **诊断能力**：适配器支持 `Features::TIMESTAMP_QUERY` 时，wgpu 后端按 pass 写时间戳并
   用 `Queue::get_timestamp_period()` 把 tick 差换算为毫秒，`pass_timings()` 与 Vulkan 同口径；
   不支持或 period 无效时降级为空切片并记一条 info 日志，不改变后端选择结果。`allocated_bytes()`
   返回渲染器主动请求且仍持有的字节数（相机 UBO、深度目标、资源缓冲与常驻查询缓冲），
   不含交换链图像、管线/着色器与驱动内部分配，不等同于 GPU 实际显存占用。
8. **保留 Vulkan**：`vulkan/` 模块、校验层、GPU 时间戳、自研显存子分配器与管线缓存均不删除，
   继续作为回退路径与显式 `--backend vulkan` 的验收目标。

## 替代方案

- **编译期 feature 二选一**：产物更小，但无法在运行时回退，也不利于同一构建做 A/B 对比。
- **抽象成 `dyn RenderBackend` 插件**：跨 crate 扩展更灵活，但当前只有两个 in-crate 后端，
  静态分发的 enum 更简单且无虚调用。
- **为 wgpu 新写 WGSL 着色器**：绑定最原生，但会产生两套着色器源与 CI 校验，偏离 ADR-0011。
- **完全移除 Vulkan**：简化维护，但失去显式同步/显存控制路径与已有验收基线。

## 后果

- 正面：默认路径跨平台、无 Vulkan 1.3 驱动也能运行；公共 API 与 extract 边界保持稳定；
  Vulkan 代码与诊断能力完整保留；两后端均可在 `--stats` 下报告每 pass GPU 耗时。
- 负面：同时构建 wgpu 与 vulkanalia，产物体积与编译时间增加；wgpu 的显存统计是请求口径，
  与 Vulkan 子分配器统计数值不可直接比较；部分适配器没有 `TIMESTAMP_QUERY`，此时 `--stats`
  仍显示无 GPU 数据；wgpu 30 的 IMMEDIATES 要求适配器支持（老旧驱动可能回退到 Vulkan
  或初始化失败）。
- 验收：`cargo test --workspace` 全绿；`--backend auto/wgpu/vulkan` 三种 headless 冒烟可区分
  生效后端；窗口路径两后端 A/B 时 PBR 画面、深度遮挡、resize、DOT dump 一致。

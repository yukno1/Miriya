# ADR 0013：资产管线与原生容器

- 日期：2026-11-26
- 状态：Accepted
- 关联：README §9.7、§10；`docs/plans/m4-asset-pipeline.md`

## 背景

`mir-asset` 原型使用同步 `load<T> -> Handle<T>`、裸 `u64` id、`HashMap<TypeId, Box<dyn Any>>` 与失败 panic，
无法支撑 1 GB 场景不卡主线程、稳定引用、依赖追踪与热重载。需要一个明确的对象模型与容器格式。

## 决策

1. **稳定 ID**：`AssetId` 用 UUIDv7，字符串表示稳定；路径只作为注册表索引，不进入运行时快照。
2. **注册表/缓存分离**：注册表只保存路径、类型标签、内容哈希、依赖；已加载内容独立缓存，避免元数据层持有大对象。
3. **错误是值**：`AssetError` 覆盖 NotFound/InvalidPath/Io/Corrupt/Version/Decode/Watch/Unsupported/Cycle/MissingDependency/Busy；解析路径禁止 panic。
4. **纯数据边界**：资产导入只产出 `MeshData`/`MaterialData`/`ImageData`/`AudioData` 等纯数据；GPU 对象由应用层在 `mir-render` 创建，维持 ADR-0012。
5. **异步与热重载**：IO/哈希/解码/解压在 rayon 作业池；主线程 `poll()` 完成队列；`notify` 事件按内容哈希比对，反向依赖闭包拓扑失效。
6. **`.miasset` 容器**：`MIRI` magic + version + schema hash + 64 KiB 分块 zstd + FNV checksum；坏块与版本不匹配可诊断。
7. **坐标转换集中**：glTF Y-up→Z-up、米→厘米、手性翻转只在 `mir-math::interop` 的 glTF 适配函数，导入报告记录转换节点。

## M4 落地补记（2026-11-26）

- `.miasset` 使用 `MIRI` magic、version 1、schema hash `miAS`、64 KiB zstd 分块与 FNV checksum；
  `encode_with_version` 专供版本不匹配负例测试。
- KTX2 仅做 identifier/尺寸/vkFormat 解析与字节透传，GPU 压缩纹理采样留待 M5。
- OGG 通过 symphonia 解码为交错 f32 PCM；WAV 支持 8/16-bit PCM，FLAC 留待后续。
- 本机 MSVC 18 对 `zstd-sys` 的 `/Z7` 调试记录报 D8050；workspace profile 仅为该 C 依赖关闭 debug 信息。
- `clap` 固定到 4.6.1（4.6.10 要求的 `clap_derive 4.6.9` 不在当前索引）。

## 替代方案

- **继续 `dyn Any` 同步缓存**：改动最小，但无法异步化、稳定引用和错误恢复，否决。
- **直接序列化 UE `.uasset`**：许可与格式复杂度高，且项目不做运行时 UE 资产兼容，否决。
- **把纹理/GPU 资源创建的 API 放进 `mir-asset`**：会令资产层依赖 Vulkan，破坏分层，否决。
- **不做容器压缩**：实现简单，但 1 GB 场景冷加载与包体预算不可控，否决。

## 后果

- 正面：稳定引用、错误可恢复、异步不阻塞主线程、依赖图可支撑 cook/热重载；容器可 fuzz 与版本化。
- 负面：API 与原型不兼容（但当前无调用点）；需维护 UUID/zstd/notify/导入器依赖；纹理 GPU 上传仍留 M5。
- 验收：容器 golden、损坏输入、版本不匹配、glTF 单位转换、热重载 ≤ 200 ms、1 GB 冷加载主线程阻塞 ≤ 16 ms。

# ADR 0006：C# 脚本运行时

- 日期：2026-11-18
- 状态：Accepted
- 关联：README §9.13、§11.1
- 修订：2026-11-23 M0 复核，基线定为 .NET 11（详见「版本基线复核」）

## 背景

需要选择玩法脚本语言与运行时方案。UE 使用蓝图与 UnrealScript/C++ 混合；团队希望用现代静态语言、
能在标准 IDE 中编辑调试，并支持热重载，同时不把引擎变成通用虚拟机。

## 版本基线复核（M0，2026-11-23）

README §11.1 要求固定 .NET 版本并在 M 里程碑复核。复核结论：

| 版本 | 发布 | 终止支持 | 结论 |
|---|---|---|---|
| .NET 10 | 2025-11 | 2028-11-14 | 可选 |
| .NET 11 | 2026-11 | 2028-11-14 | ✅ 采用 |

两者的终止支持日期相同——.NET 11 虽是 STS（2 年支持），但因晚一年发布，
支持终点与 .NET 10（LTS，3 年）一致，均为 2028-11-14。在支持周期等价的前提下选用更新的版本，
可获得更新的语言特性、运行时性能改进与工具链支持，且无需承担提前退役的风险。

故基线定为 **.NET 11**（`global.json` 锁定 `11.0.100`，
`TargetFramework = net11.0`，CI `setup-dotnet@11.0.x`）。

## 决策

1. **C# 是唯一的玩法脚本语言**；不使用蓝图、节点图或 WASM 脚本。玩法规则由 C# 实现（§9.12），
   通用流程留在 Rust。
2. **托管方式**：.NET 11 通过 `hostfxr`（`netcorehost`）在进程内加载；
   `global.json` 固定 SDK，`miriya build` 调用标准 `dotnet build` 编译用户程序集。
3. **边界只有版本化 C ABI**：表驱动函数指针 + 不透明 64 位句柄；C# 侧生成 `SafeHandle`，引擎校验句柄世代；
   禁止裸指针跨边界；字符串统一 UTF-8 + 显式所有权。Rust 不依赖 .NET 内部结构，C# 不持有裸 Rust 指针。
4. **异常**：托管异常在 C ABI 边界转换为引擎错误码并附 C# 栈，禁止跨 `extern "C"` 展开。
5. **序列化**：场景只保存 C# 类型名/稳定路径与参数，不序列化托管对象图；加载时由脚本重建实例。
6. **热重载**：用户程序集放入可卸载 `AssemblyLoadContext`，文件监听 + `dotnet build`，
   按稳定对象 ID 重新绑定，目标 ≤ 1 s；失败则回退重启 PIE。
7. **线程约束**：脚本只在主线程 `update` 阶段执行；禁止在渲染/音频线程调用托管代码；不为每实体做 P/Invoke，
   性能敏感路径留在 Rust。
8. **安全与发布**：用户程序集是受信代码（非沙箱）；随包分发 .NET 11 自包含运行时，Native AOT 列为后续可选优化。
9. **验收**：C# 驱动玩家移动、生成/销毁 Actor、订阅输入；热重载 ≤ 1 s；打包后无需安装 SDK。

## 替代方案

- **蓝图/节点图**：可视化门槛低，但工具链与运行时复杂，且与「clean-room、Rust 优先」冲突。
- **WASM 脚本**：沙箱好但调试体验与 .NET 生态割裂，绑定与 GC 交互复杂。
- **Lua / Python**：动态语言性能与类型安全不足，IDE 调试体验弱。
- **纯 Rust 玩法**：性能最佳但迭代慢、热重载困难，无法满足设计师与快速玩法验证需求。

## 后果

- 正面：标准 `.csproj` 可在 VS/Rider/VS Code 编辑调试；版本化 ABI 隔离了 .NET 版本演进；热重载支持快速迭代。
- 负面：进程内托管运行时增加启动时间与包体（自包含 .NET 11）；C ABI 绑定生成与句柄校验是 M8 的重点工作量。
- 待办：M0 的 PoC 仅完成 Vulkan 部分；.NET 11 hostfxr 托管的最小 PoC 需在 M8 前补做。

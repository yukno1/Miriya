# ADR 0012：渲染帧数据与相机提交边界

- 日期：2026-11-23
- 状态：Accepted
- 关联：README §5.1、§8.2（M2）、§9.2、§9.6、§14；ADR 0003、ADR 0004、ADR 0011；`docs/plans/v0.2-cube.md`

## 背景

v0.2 要在窗口里绘制 3×3 立方体阵列与中心自转立方体，并提供自由飞行相机。此前 `mir-render` 的公共 API
只有 `begin_frame(clear)` / `end_frame()`，没有相机与实例提交入口；渲染器若直接读取 `mir-scene`/ECS，
会违反 ADR 0004 第 3 条“extract 阶段产出纯帧数据、渲染层不依赖场景”的边界。
Vulkan 侧已具备立方体顶点缓冲、UBO 描述符、push constants 与索引绘制，需要一个稳定的数据契约把这些能力接到应用层。

## 决策

1. **extract 边界**：`mir-render` 只接收 `CameraFrame`、`MeshHandle`、`InstanceData`（及 `MeshData` / `Vertex`），
   不依赖 `mir-scene`、`mir-ecs` 或 `winit`；应用层遍历世界并把 `Transform` 提取为 `InstanceData::model`。
   公共 API 不出现 Vulkan 类型。
2. **提交接口**：`begin_frame` 清空上一帧绘制请求；`set_camera` 记录相机 view-projection；`submit` 收集
   （网格，实例）对；`end_frame` 录制并呈现。`submitted_instances()` 供测试与诊断。
3. **UBO / push constants 划分**：相机 `view_proj`（64 B）放 descriptor set 0 / binding 0 的 `UNIFORM_BUFFER`；
   逐实例 `model` + `tint`（80 B）放 push constants，低于 `maxPushConstantsSize` 保证的 128 B 下限。
   这样 M5 的材质/纹理可以直接扩展描述符，而不需要改变实例提交 API。
4. **相机数学位置**：相机类型、yaw/pitch 与自由飞行控制器放在 `mir-scene`，只依赖 `mir-math`，不依赖
   `mir-input` 或窗口；应用层把键盘/鼠标状态翻译成 `CameraInput`。投影继续使用 `glam::camera::lh::proj::vulkan`
   与 `Mat4::look_to`，坐标翻转只在 `mir-math` 相机函数里发生（ADR 0003）。
5. **临时取舍**：v0.2 保持单帧在飞行、每资源一次 Vulkan 内存分配、阻塞式网格上传；RenderGraph、多帧在飞行、
   显存子分配器仍属 M2 剩余范围（ADR 0004 第 2/4/6 条）。
6. **校验层**：`EngineConfig::validation` 控制 Vulkan 校验层，debug 默认开启、单元测试默认关闭，命令行
   `--validation` / `--no-validation` 可覆盖；layer 或 debug utils messenger 缺失时警告降级，不 panic。
   消息经 `mir-log` 输出，携带消息类型、ID 与少量对象名。
7. **单位约定（M3 已校准）**：ADR 0003 规定厘米、Z-up、左手系。v0.2 曾临时按 **1 单位 = 1 米**；
   M3 已通过 `mir-math::interop` 把演示数据、相机 near/far/速度与快照统一为厘米，
   渲染层保持单位无关（`CameraFrame::camera_position` 注释同步为厘米）。

## 替代方案

- **让 `mir-render` 直接遍历 ECS World**：省去 extract 代码，但会把渲染器与场景/ECS 绑定，违反 §5.1 依赖规则。
- **把所有数据放进 UBO**：实现简单，但每个实例都要更新描述符或动态偏移，不如 push constants 适合小实例数据。
- **相机控制放应用层**：可行但难以 headless 单测，且与后续编辑器视口相机重复；放入 `mir-scene` 更利于复用。
- **v0.2 就上多帧在飞行 / RenderGraph**：正确但显著扩大改动面，会掩盖立方体绘制本身的正确性问题。

## 后果

- 正面：应用层只做数据提取，渲染层边界清晰；相机与输入解耦、可单测；校验层问题能通过统一日志定位。
- 负面：单帧在飞行与阻塞上传已由 M2 剩余的 2 帧在飞行/显存子分配器改善，但阻塞上传仍待 M4 评估；
  演示单位偏差已在 M3 修正。
- 准入：10 个实例在 1080p 下稳定呈现、深度遮挡正确、Vulkan 校验层 0 error；`cargo run -- --headless --frames 1000`
  与窗口 600 帧回归均通过。

## 3. 关键技术决策（v0.2 采用）

1. **手性对齐 ADR-0003**：`mir-math` 的投影/视图全部改 `glam::camera::lh`；相机 `up = +Z`、`forward = +X`。
   投影保持 Vulkan 约定（深度 0..1、NDC Y 向下），转换只在 `mir-math` 的相机函数里发生，业务代码不得手写翻转
   （ADR-0003 第 3/4 条）。
2. **相机数据用 UBO，逐实例数据用 push constants**。`maxPushConstantsSize` 保证下限 128 B：
   `mat4 model (64) + float4 tint (16) = 80 B` 安全；相机 `view_proj (64 B)` 放 `binding 0` 的 UBO。
   这样 v0.2 就打通 descriptor 路径，M5 的材质/纹理直接扩展，避免后续推倒重来。
3. **帧数据契约**：`mir-render` 只接受纯数据（`Mat4` + `[f32;3]` + 索引数组），**不依赖 `mir-scene`/`mir-ecs`**；
   `miriya-app` 在 `on_render` 里做 extract（遍历 `Transform` → `InstanceData`）。写 ADR-0012 固化该边界。
4. **网格上传用 staging + `cmd_copy_buffer`，阻塞式**（提交后 `device_wait_idle`）。v0.2 只有 1–2 个网格，
   阻塞成本可忽略；异步上传/自研分配器归 M2 剩余与 M4。
5. **单帧在飞行保持现状**。多帧在飞行（2–3）需要每帧独立命令池/UBO/描述符，属 M2 剩余；v0.2 不承担该复杂度。
6. **校验层按构建类型默认开启**：`EngineConfig::validation` 默认 `cfg!(debug_assertions)`，测试内默认关闭避免 CI 噪音；
   `--validation` / `--no-validation` 可覆盖。layer 不存在时 `warn` 后继续，绝不 panic。
7. **背面剔除**：网格的模型空间绕序统一为"从外部看向面中心为逆时针"，由 CPU 单测断言；
   由于 Vulkan NDC 为 Y 向下（glam `vulkan::perspective` 会翻转 Y），投影后绕序变顺时针，管线初值取
   `FrontFace::CLOCKWISE` + `CullMode::BACK`，首帧实测确认；若相反只改 `front_face` 并留注释，不改网格。

## 5. 分阶段详述

### 批次 A：数学与契约（V-01…V-05，3.0 d）

#### V-01 `mir-math` 手性修正（1.0 d）

- 改动：`Mat4::perspective` → `glam::camera::lh::proj::vulkan::perspective`；`Mat4::look_at` → `lh::view::look_at_mat4`；
  新增 `Mat4::look_to(eye, forward, up)`（`lh::view::look_to_mat4`）；文档统一写"左手系、Z-up、Y-up 视空间"。
- 顺手修正 `transform_point` 的文档（`transform_point3` 不做透视除法）。
- 单测：
  - `look_to(eye=(0,0,0), forward=+X, up=+Z)` 把 `(1,0,0)` 变换到视空间 `(0,0,1)`（LH 视空间 +Z 向前）。
  - `perspective(fov=90°, aspect=1, near=1, far=100)`：视空间 `(0,0,1)` → NDC z ≈ 0，
    `(0,0,100)` → NDC z ≈ 1；视空间 `(0,1,10)` → NDC y < 0（Y 向下，即世界上方在屏幕上方）。
  - 用 `Mat4` 的 Deref 取 `inverse()`，验证 `view * inverse(view) == IDENTITY`。
- 验收：`cargo test -p mir-math`；全仓库无 `camera::rh` 残留。

#### V-02 `Transform` 增加旋转（0.5 d）

- `Transform { position: Vec3, rotation: Quat, scale: Vec3 }`，`Default` 全单位；`to_matrix(&self) -> Mat4` 用
  `Mat4::from_trs`（先缩放、再旋转、后平移）。
- 同步 `miriya-app` 的 `Transform { .. }` 字面量为 `..Default::default()`。
- 单测：平移+旋转 90°+缩放 2 的组合点变换结果；`mir_ecs::Component` 仍成立。
- 不做：把 `Transform` 迁到 `mir-math`（ADR-0003 第 6 条，M3 再迁）。

#### V-03 `Camera` 类型（0.5 d）

```rust
pub struct Camera {
    pub position: Vec3,
    pub yaw: f32,     // 绕 +Z；正 = 右转（X→Y）
    pub pitch: f32,   // 绕 -Y；正 = 抬头；clamp ±89°
    pub fov_y: f32,   // 弧度，默认 60°
    pub z_near: f32,  // 默认 0.1（当前演示按 1 单位 = 1 米）
    pub z_far: f32,   // 默认 1000
}
```

- `forward()`：`Quat::from_rotation_z(yaw) * Quat::from_rotation_y(-pitch) * Vec3::X`。
- `view()`：`Mat4::look_to(position, forward(), Vec3::Z)`；`projection(aspect)`；`view_projection(aspect)`。
- `impl mir_ecs::Component for Camera`（供后续 PIE/编辑器拾取）。
- 单测：`yaw=0,pitch=0 → forward=+X`；`yaw=π/2 → +Y`；`pitch=π/4 → z≈+0.707`；pitch clamp 后 forward 不为零。

> 单位说明：ADR-0003 要求厘米，但当前 `miriya-app` 的移动速度（5 单位/秒）与窗口/相机参数实际按米设计。
> v0.2 演示统一按 **1 单位 = 1 米**（立方体边长 2、相机 near 0.1 / far 1000），并在 ADR-0012 的"遗留"里登记
> "演示单位与 ADR-0003 厘米约定不一致，M3/M4 资产导入前必须校准"。不要在本批次里改全局单位，否则会牵动
> 物理契约与后续资产导入。

#### V-09 深度缓冲（1.5 d）

- `find_depth_format`：`D32_SFLOAT` → `D32_SFLOAT_S8_UINT` → `D24_UNORM_S8_UINT`（用
  `get_physical_device_format_properties` 校验 optimal tiling + depth-stencil attachment；仅用深度，不必 STENCIL）。
- 深度图像 + `vkAllocateMemory`（`find_memory_type`）+ 视图；创建时一次性命令把 layout 置为
  `DEPTH_ATTACHMENT_OPTIMAL`；resize 时重建。
- 管线补 `PipelineDepthStencilStateCreateInfo`（`depth_test_enable`、`depth_write_enable`、`LESS`）；
  动态渲染 `RenderingInfo::depth_attachment`（`load_op CLEAR`、`clear_value.depth = 1.0`、`store_op DONT_CARE`）。
- 验收：立方体自遮挡正确；validation 无 layout/attachment 报错；resize 后深度仍正确。

#### V-10 交换链布局与呈现健壮性（1.0 d）

- 每帧 acquire 后 barrier：`UNDEFINED → COLOR_ATTACHMENT_OPTIMAL`（内容本来就会清空，声明 `UNDEFINED` 是合法且无需跟踪历史状态的做法），
  `srcStage COLOR_ATTACHMENT_OUTPUT` / `dstStage COLOR_ATTACHMENT_OUTPUT`、`dstAccess COLOR_ATTACHMENT_WRITE`。
- 渲染结束 barrier：`COLOR_ATTACHMENT_OPTIMAL → PRESENT_SRC_KHR`，`srcAccess COLOR_ATTACHMENT_WRITE`，
  `srcStage COLOR_ATTACHMENT_OUTPUT` / `dstStage BOTTOM_OF_PIPE`（legacy barrier，不用 sync2 的 `NONE`）。
- `queue_present_khr` / `acquire_next_image_khr` 返回 `OUT_OF_DATE`/`SUBOPTIMAL` → 标记需重建、本帧不当作错误、下一帧重建；
  `RenderContext::resize(0,0)`（最小化）跳过重建并保留旧 extent，恢复时再建。
- 验收：拉大/缩小窗口、最小化、恢复、Alt+Tab 多次，validation 0 error，无 `frame_error` 残留。

**release 构建暴露并修复的 UB**：`init_pipeline` 中 `WriteDescriptorSet::buffer_info(&[buffer_info])` 传入了临时数组，
vulkanalia builder 只保存指针；release 优化后指针失效，校验层报 `VkDescriptorBufferInfo` 无效句柄/offset，
进程最终 `STATUS_ACCESS_VIOLATION`。改为命名 `buffer_infos` 数组后，release 600 帧与校验层均通过。
该问题说明“debug 校验层 0 error”不足以覆盖优化构建的生命周期问题，后续 unsafe 审查需把 builder 指针生命周期列为检查项。
